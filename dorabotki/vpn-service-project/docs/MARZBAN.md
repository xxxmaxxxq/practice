# 🛡 Панель Marzban и выдача ключей

Этап, после которого бот начинает выдавать **настоящие рабочие ключи VPN**.
До него подписка создавалась в базе, но конфигов внутри не было — их некому
было генерировать.

---

## Что появится

| Компонент | Роль |
|---|---|
| **Marzban** | Панель: аккаунты Xray, ключи, ноды, статистика трафика |
| **Xray (ядро в Marzban)** | Принимает подключения клиентов по VLESS + Reality |
| **panel.ваш-домен** | Веб-интерфейс панели, только для вас |
| **vpn.ваш-домен** | Клиентская часть: подписки, импорт, Mini App |

Панель вынесена на **отдельный субдомен** намеренно: у Marzban свои пути
`/api/*`, и на одном домене они столкнулись бы с `/api/miniapp/*` сервиса.

---

## Про порт 8443

На мастер-сервере порт 443 занят Caddy — он обслуживает HTTPS для подписок
и Mini App. Поэтому VLESS слушает **8443**.

Это рабочий вариант, но со своей ценой: часть корпоративных и гостиничных
сетей выпускает наружу только 443. Когда появится отдельный сервер под ноду,
Reality переедет на 443 и этот минус исчезнет. Менять при этом придётся
одну строку — порт в конфиге ноды.

---

## Почему рядом с панелью работает маленький проброс

Marzban без SSL-сертификатов слушает только `127.0.0.1` — это его встроенное
поведение, а не ошибка: панель не хочет светиться в интернет без шифрования.
Но тогда до неё не достучаться и соседним контейнерам.

Выдавать панели самоподписанный сертификат ради внутренней связи — лишняя
сложность. Вместо этого рядом живёт контейнер `marzban-proxy` (socat) в том же
сетевом пространстве: он отдаёт localhost панели на порт 8080. Снаружи HTTPS
по-прежнему терминирует Caddy, а бот и API обращаются к `http://marzban:8080`.

## Развёртывание

### 1. Вторая A-запись

В панели регистратора добавьте ещё одну запись — на тот же IP:

| Тип | Субдомен | Значение |
|---|---|---|
| A | `panel` | IP мастер-сервера |

### 2. Настройки в `.env`

```bash
echo 'PANEL_BASE_URL=https://panel.ваш-домен' >> .env
echo 'MARZBAN_USERNAME=admin' >> .env
echo "MARZBAN_PASSWORD=$(openssl rand -hex 16)" >> .env
echo 'SERVICE_NAME=SaltVPN' >> .env
```

Пароль панели посмотрите потом в `.env` — он понадобится для входа.

### 3. Запуск

```bash
bash scripts/deploy-master.sh
```

Что делает скрипт:

1. проверяет обе A-записи и сверяет их с IP сервера;
2. собирает образы;
3. генерирует ключи Reality (X25519) — если ключи уже есть, **переиспользует**,
   иначе перевыпуск разорвал бы работающие подписки;
4. собирает конфиг Xray из шаблона и кладёт его в том панели **до** первого
   старта: без файла ядро Xray не поднимется;
5. поднимает Marzban, бота, API, воркеры и Caddy;
6. дожидается панели и прописывает ноду — и в саму панель (host: адрес, порт,
   SNI), и в базу сервиса (чтобы работали тарифы и Auto-Healing).

### 4. Проверка

```bash
bash scripts/deploy-master.sh status     # все контейнеры running
curl https://vpn.ваш-домен/health        # {"status":"ok",...}
```

Откройте `https://panel.ваш-домен`, войдите под `MARZBAN_USERNAME` и
`MARZBAN_PASSWORD`. В разделе Inbounds должен быть `VLESS_REALITY_nl-1`.

Затем в боте: `/start` → «🎁 Попробовать 3 дня бесплатно» → «⚡ Подключить
в 1 клик». Happ импортирует подписку, и внутри уже будет рабочий сервер.

## Где что лежит

| Что | Где |
|---|---|
| Ключи Reality | `config/generated/reality-keys.json` (в git не попадает) |
| Конфиг Xray | `config/generated/xray_config.json` + том `salt_marzban_data` |
| База панели | том `salt_marzban_data` |
| База сервиса | том `salt_bot_data` |

Посмотреть ключи: `bash scripts/deploy-master.sh keys`

## Вторая нода (российская)

Когда мастер заработает, российский сервер подключается как отдельная нода:

1. В панели: *Nodes → Add Node*, скопировать сертификат.
2. На российском сервере: `bash scripts/install-node.sh`, вставить сертификат.
3. На мастере прописать ноду в базе сервиса:

```bash
docker compose -f docker/docker-compose.master.yml exec api \
  python -m app.cli add-node --code ru-1 --location ru --host 185.246.220.115
```

После этого тариф «🇷🇺 Россия» начнёт выдавать ключи на неё, а «🌍 Мульти» —
на обе локации сразу.

## Частые вопросы

**Ключ импортировался, но интернет не идёт.**
Проверьте, что порт 8443 открыт: `ufw allow 8443` на сервере. И что в панели
у пользователя статус `active`.

**В панели нет inbound VLESS_REALITY_nl-1.**
Значит конфиг Xray не доехал. Посмотрите логи панели:
`docker logs salt_marzban --tail 50` — там будет причина (чаще всего
невалидный JSON после ручной правки).

**Хочу сменить маскировочный домен.**
```bash
XRAY_SNI=www.samsung.com bash scripts/deploy-master.sh
```
Ключи при этом сохранятся, поменяется только SNI.

**Нужно всё пересоздать с нуля.**
```bash
bash scripts/deploy-master.sh stop
docker volume rm salt_marzban_data
rm -rf config/generated
bash scripts/deploy-master.sh
```
Осторожно: выданные ранее ключи перестанут работать.
