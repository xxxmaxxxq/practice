## Что сделано

### 1. Меню бота и разделы (как у Atom и Quattro)

**Синяя кнопка «Меню» рядом с полем ввода.** Регистрируется при каждом старте
бота (`app/bot/main.py` → `BOT_COMMANDS`, `setup_bot_menu`):

| Команда | Раздел |
|---|---|
| `/start` | 🏠 Главное меню |
| `/account` | 👤 Личный кабинет |
| `/buy` | 💳 Покупка и продление |
| `/connect` | ⚡ Подключение и ключи |
| `/ref` | 👥 Пригласить друзей |
| `/help` | 📖 Помощь и инструкции |
| `/support` | 💬 Поддержка |

Чтобы изменить список — правится один массив `BOT_COMMANDS` и перезапуск бота.

**Кнопка «🏠 Главное меню»** добавлена внизу всех вложенных экранов
(подключение, помощь, тарифы, рефералы, поддержка, лечение) — из любого места
переписки можно вернуться в начало одним тапом.

**Экран главного меню** (`app/bot/handlers/menu.py`) подстраивается под человека:
новичку показывается кнопка триала, подписчику — продление.

```
🎁 Попробовать 3 дня бесплатно
👤 Личный кабинет   |  💳 Купить подписку
⚡ Подключить в 1 клик | 👥 Пригласить друзей
📖 Инструкция        |  💬 Поддержка
📊 Открыть кабинет
```

**Новый экран «Помощь»** (`/help`): инструкции по iPhone, Android, Windows,
macOS, ответы на частые вопросы (устройства, заморозка, «перестало работать»)
и кнопки установки приложений. Текст — в `config/messages.yml` → ключ `help`.

### 2. Прямое открытие Happ (как у Мистера Кло)

Схема, которую вы видели на скриншотах 4–5, в проекте уже была, но не работала
без домена. Теперь доведена до рабочего вида:

- страница `/i/{token}` переоформлена под тот же сценарий: «🚀 Открываем Happ…»,
  крупная кнопка «Перейти в Happ», автоматический переход через 0.6 с,
  остальные приложения и ссылка-подписка спрятаны под раскрывающийся блок;
- добавлена связка **бот + сайт + HTTPS** (`docker/docker-compose.bot-web.yml`
  и `docker/Caddyfile.web`): Caddy сам выпускает сертификат Let's Encrypt;
- скрипт `scripts/deploy-web.sh` перед запуском проверяет домен: резолвится ли
  он, указывает ли A-запись на этот сервер, свободны ли порты 80 и 443,
  и после старта сам дёргает `https://домен/health`;
- бот при старте предупреждает в логах, если `PUBLIC_BASE_URL` не https —
  именно поэтому сейчас в сообщении видна ссылка `http://localhost:8000/sub/...`
  и нет кнопки: Telegram не принимает такие адреса в кнопках.

### 3. Одна база на два процесса

Бот и API теперь работают с общим файлом SQLite, поэтому в `app/db.py` включён
журнал WAL и увеличен таймаут ожидания — без этого второй процесс падал бы
с ошибкой «database is locked».

## Что нужно от вас

**Домен.** Без него кнопка «⚡ Подключить в 1 клик» не появится: Telegram
пропускает в кнопки только `https://`. Порядок такой:

1. Купить домен (подойдёт `.top`, `.click`, `.xyz` — около 200 ₽/год).
2. В панели регистратора создать A-запись на IP вашего сервера.
3. В `.env` указать `PUBLIC_BASE_URL=https://ваш-домен`.
4. Запустить `bash scripts/deploy-web.sh` — сертификат выпустится сам.

Пришлите домен — впишу в конфиг и дам готовые команды.

## Как перенести доработки

Вариант простой: заменить рабочую папку копией.

```bash
cd ~/salt-bot/repo
cp -r dorabotki/vpn-service-project/. vpn-service-project/
cd vpn-service-project
bash scripts/deploy-bot.sh update
```

Файл `.env` не перезапишется — в копии его нет.

Вариант аккуратный: посмотреть разницу и перенести по частям.

```bash
diff -ru vpn-service-project dorabotki/vpn-service-project | less
```
